# AteliersAR

WebAR ateliers built with 8thWall Studio: you scan an image (image target) and 3D content (GLB) appears on it. Each atelier is its own 8thWall project with its own URL, listed on a home page.

Extracted from the AR demo of [ori-co.github.io](https://github.com/ori-co/ori-co.github.io) (`ardemo-studio/`).

## Stack

- **8thWall Studio** (desktop app) to edit the scenes. It reads and writes an atelier folder directly.
- **`@8thwall/ecs`** runtime (entity-component system) and **`@8thwall/engine-binary`** (XR engine: SLAM, image targets).
- **webpack 5** + TypeScript for the build, using the scaffolding generated by Studio in `config/`.
- 3D models as **GLB**, converted from Tinkercad OBJ exports by `/add-model` (Python: `numpy`, `trimesh`, `networkx`).
- **Netlify** serving the repo root, deployed automatically from `main`.

## Project layout

The repo root **is the static site**: `index.html` is the home page, and each `<slug>/` folder is the build of an atelier, served at `/<slug>/`. Both are generated by `/deploy`: never edit them by hand.

```
AteliersAR/
├── index.html            # GENERATED home page: one entry per deployed atelier (title, client / place)
├── <slug>/               # GENERATED build of an atelier → URL /<slug>/
├── template/             # Base 8thWall Studio project, copied for each new atelier
├── ateliers/
│   └── <slug>/           # Source: one full 8thWall Studio project per atelier
├── home/index.html       # Home page template (the list is filled in at deploy time)
├── deploy.config.json    # url: where the site is served, to check on the device
├── .claude/skills/       # new-atelier, add-target, add-model, deploy
├── CLAUDE.md
└── README.md
```

The host serves the whole repo, so the sources (`template/`, `ateliers/`…) are reachable too if someone knows the path. Every page is `noindex`. If the host lets you exclude folders from publishing, exclude everything but `index.html` and the build folders.

## Workflow: a new atelier

1. **Create the atelier**: `/new-atelier`. It copies `template/` to `ateliers/<slug>/` and writes `atelier.json`, the atelier's entry on the home page (title, client / place, date). The entry only shows up on the site after the first deploy (step 4).
2. **Add the image targets**: `/add-target <slug> <image>`, **Studio closed**. It generates the target files, loads them in `src/app.js` and adds an empty Image Target entity to the atelier's scene (see [Image targets](#image-targets)). Run it once per image.
3. **Add the 3D models**: `/add-model <slug> <zip> <target>`, once per `.zip` in the atelier's `scenes/` folder (one zip = one Tinkercad OBJ export, `.obj` + `.mtl`). It converts it to GLB in `src/assets/` (`obj2glb.py`: colors from the MTL, Z up → Y up) and adds it to the scene **under the Image Target entity** of that target, standing on the image, its largest dimension scaled to 0.6 target units (`--size` to change it). Size and placement are a first guess: check them on the device.
4. **Publish**: `/deploy <slug> "<label>"` builds the atelier into `<slug>/` at the repo root and regenerates the home page (see [Build & deploy](#build--deploy)). Then commit and push to `main`: **Netlify deploys `main` automatically**. Test on the real device at `<url>/<slug>/`.

## Ateliers

An atelier is a folder of `ateliers/`, created by `/new-atelier` as a copy of `template/`. It is a complete, standalone 8thWall Studio project: open **that folder** in Studio, not the repo root.

```
ateliers/<slug>/
├── atelier.json          # Home page entry: title, client (client / place), date (YYYY-MM-DD, sorts the list)
├── src/
│   ├── .expanse.json     # The scene: entities, transforms, components. Written by Studio.
│   ├── app.js            # XR8 config: list of image targets to load
│   ├── target-events.ts  # Forwards image found/lost to the HTML overlay
│   ├── index.html        # HTML shell + overlay (version label, "find the image" hint)
│   └── assets/           # GLB models used by the scene
├── image-targets/        # Image target files (.json + 4 images each)
├── photos/               # Image target photos (.jpg/.png), to print. Copied to the build, adds the "Images" gallery button
├── video/                # Optional: one video of the whole experience (.mp4/.webm/.mov, portrait). Copied to the build, adds a "Vidéo" button
├── scenes/               # Source 3D scenes as .zip (OBJ + MTL + textures), converted to GLB in src/assets/. Not part of the build
├── config/               # 8thWall webpack scaffolding (normally leave alone)
├── node_modules/         # Own dependencies (git-ignored, installed by /deploy)
├── dist/                 # Build output (git-ignored)
└── package.json
```

- **The slug is the URL** (`/<slug>/`): lowercase letters, digits, hyphens, e.g. `2026-10-salon-vivatech`. `template`, `ateliers`, `home` and `node_modules` are reserved (root folders). Renaming a deployed atelier leaves the old build folder online: delete it by hand.
- **Each atelier is frozen**: code, overlay and dependencies are copied, not shared. Improving `template/` only affects ateliers created afterwards, so a past atelier keeps working as delivered. Port a fix to an old atelier by hand if needed.
- `template/` is a valid Studio project too: open it in Studio to change the starting scene. The scripts accept `template` as slug (except `/deploy`).

How the build is wired (`config/`, in each project):

- `entry-plugin.js` generates a virtual entry that **imports every `.ts` / `.js` file in `src/`** (except `src/assets/`), then calls `ecs.application.init()` with `.expanse.json`. A new component file only has to exist in `src/` to be bundled.
- `@8thwall/ecs` is declared as an external mapped to `window.ecs`, which `runtime.js` defines. Just `import * as ecs from '@8thwall/ecs'` as usual.
- Files in `src/assets/` are imported as **path strings** (`asset-loader.js`) and copied to `dist/assets/`.
- The runtime and XR engine are copied from `node_modules` to `dist/external/{runtime,xr}/`.

## Scene

Starting scene of `template/` (`src/.expanse.json`). Studio is the source of truth, so check it there if in doubt:

```
Default Space
├── Ambient Light
├── Directional Light          (disabled, see gotchas)
└── Camera                     phone: AR · world tracking
```

No image target: `image-targets/` is empty and `src/app.js` loads nothing. Each atelier adds its own.

A pair = one Image Target entity with its GLB model(s) as children. Add the target with `/add-target <slug> <image>`, then the model with `/add-model <slug> <zip> <target>` (or drop a GLB in the atelier's `src/assets/` and put it under the entity in Studio).

## `target-events` (`src/target-events.ts`)

Not a component: a world behavior (`ecs.registerBehavior`), so it needs nothing in the scene. It listens to `ecs.events.REALITY_IMAGE_FOUND` / `REALITY_IMAGE_LOST` on `world.events.globalId` and re-emits them on `window` as `ar-image-found` / `ar-image-lost` (target name in `detail`). This is how the HTML overlay reacts to tracking.

To write a custom component, follow this pattern (see the gotchas below):

```ts
import * as ecs from '@8thwall/ecs'

ecs.registerComponent({
  name: 'my-component',            // name referenced by the scene in .expanse.json
  schema: {},                      // even if empty (see gotchas)
  add: (world, component) => {     // arrow function (see gotchas)
    const eid = component.eid
    world.events.addListener(eid, ecs.input.SCREEN_TOUCH_START, () => {
      // …
    })
  },
})
```

Then attach it to an entity in Studio.

## HTML overlay (`src/index.html`)

Plain HTML/CSS on top of the AR canvas. Restyle it through the CSS variables on `.ar-ui`. The overlay root has `pointer-events:none`, so taps reach the AR canvas: give `pointer-events:auto` to any element that must catch taps.

- **Version label** (`id="ar-version"`, top right): shows which build actually runs on the phone (host and browser caches). **Update it with every deploy**, `/deploy <slug> "<label>"` does it. Convention: `V<major>.<minor> - <what changed>`.
- **Back** (top left): link to `../`, the home page.
- **Hint** (`id="ar-hint"`): "find the image", hidden on the first `ar-image-found`. If the atelier has photos, it adds a line pointing to "Images" to print one.
- **Images** (`id="ar-gallery-open"`): only shown if the atelier's `photos/` folder holds images (.jpg/.png). The build copies them to `dist/photos/` with a `photos/index.json` file list. It opens a full-screen gallery explaining that an image can be printed to try the AR, with a download link under each image (no "download all": each participant only wants their own drawing). They are public once deployed: only put images meant to be shared.
- **Video** (`id="ar-video-open"`): only shown if the atelier's `video/` folder holds a video (the first file, alphabetically). The build copies it to `dist/video/` with a `video/index.json` file list. The tap opens it full screen and plays it: Fullscreen API + portrait lock on Android, native player on iPhone. Use H.264 MP4 for iPhone, and keep it light (it is served from the repo).

The page has `<meta name="robots" content="noindex">`, like the home page: the site is reachable by link only.

## Image targets

Paths below are relative to the atelier folder.

1. Upload the image in Studio. It generates `image-targets/<Name>.json` plus `_original`, `_cropped`, `_luminance` and `_thumbnail` images.
2. Register the JSON in `src/app.js`:
   ```js
   XR8.XrController.configure({
     imageTargetData: [require('../image-targets/<Name>.json')],
   })
   ```
3. On the Image Target entity, select the same target. **The target name in the scene must match the `name` field of the JSON.** Otherwise nothing is tracked, and no error is shown.
4. Remove old targets from both `app.js` and `image-targets/`. Every target listed in `app.js` must exist on disk, or the build fails on the `require`.

Shortcut: the `/add-target <slug> <image>` skill does steps 1–3 from a JPG/PNG without Studio (it reproduces Studio's files: 3:4 portrait crop, 480x640 grayscale luminance, 263x350 thumbnail) and adds an empty Image Target entity to the scene. Landscape images are rotated 90° clockwise first, as Studio does.

## Build & deploy

From an atelier folder:

```sh
npm ci               # once per atelier
rm -rf dist          # recommended: the build does not clean dist/
npm run build        # → dist/
```

Studio can also produce the build.

Deploying an atelier = copying `ateliers/<slug>/dist/` to `<slug>/` at the repo root, then regenerating the root `index.html`. **Other ateliers are not rebuilt nor touched.**

`/deploy <slug> ["<label>"]` runs the checks, sets the version label, installs and builds, replaces `<slug>/` and rebuilds the home page (`.claude/skills/deploy/build-home.mjs`). The home page lists every atelier that has a build folder at the root, newest first, using its `atelier.json`. Then commit and push to `main`: Netlify publishes it automatically.

`deploy.config.json` → `url` is where the site is served, used to open `<url>/<slug>/` on the device:

```json
{
  "url": "https://example.com/"
}
```

### Local testing

- Studio's preview is enough for scene layout and interactions.
- `npm run serve` starts webpack-dev-server in development mode.
- Mobile browsers only grant camera access on a secure context (HTTPS), so tracking is best tested on the device via the deployed URL.

## ECS gotchas

Lessons learned the hard way:

| Topic | What to do |
|---|---|
| Component syntax | Studio expects the arrow function form `add: (world, component) => {}`, not the method shorthand `add(world, component) {}` |
| Component without `schema` | Always declare `schema: {}`, even if empty. Otherwise Studio saves the component without `parameters`, and duplicating the entity crashes with `TypeError: Cannot convert undefined or null to object` in `createObjectUpdateRefs`. After adding it, remove and re-add the component in Studio so the scene entry gets rewritten |
| Tap on an entity | Listen on the entity itself: `world.events.addListener(eid, ecs.input.SCREEN_TOUCH_START, cb)`. Listening on `world.events.globalId` and comparing target/eid proved unreliable |
| Event payload | Events are wrapped: use `e.data.target`, not `e.target` |
| Show / hide | Use `world.getEntity(eid).show()` / `.hide()`. `ecs.Hidden.remove` doesn't bring back an entity hidden in Studio |
| `LandingPage is not defined` | Remove `XR8.addCameraPipelineModule(LandingPage.pipelineModule())` from `app.js` |
| Brightness flickering on models | Seen with the directional light on (unresolved in the original project), which is why it is disabled in the starting scene |

## Working rule

Move forward **one step at a time**, and only start the next step once the current one works **on the real device**. Desktop preview doesn't count.
